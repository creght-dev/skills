# Creght Internationalization

Creght multilingual content is field-level: one CMS item holds every language,
translations live under `_i18n`, and `talizen/cms` decodes fields to the current
locale on read. Do not create one item per language or translation-group keys.

## Enable

Add `i18n` to `talizen.config.ts`, or use editor Settings / Languages.

```ts
export default {
  i18n: {
    defaultLocale: "en",
    locales: ["en", "zh", "ja"],
    localeDetection: true,
  },
}
```

## Routing

- Default locale has no prefix: `/about`.
- Other locales are prefixed: `/zh/about`, `/ja/about`.
- The platform checks locale-specific pages first, then shared pages.
- Prefer shared pages plus locale-aware data; use per-locale files only when
  layout differs.
- Avoid `[lang]/Index.tsx` as root catch-all with default-no-prefix routing.

## Domain Routing

Locale-specific domains are supported through `i18n.domains` in
`talizen.config.ts`.

```ts
export default {
  i18n: {
    defaultLocale: "en",
    locales: ["en", "fr"],
    domains: [
      { domain: "example.com", defaultLocale: "en" },
      { domain: "example.fr", defaultLocale: "fr" },
    ],
  },
}
```

`example.fr/about` serves French without `/fr`. Locale detection or explicit
locale prefixes can redirect to the configured domain for that locale. Domains
listed here must also be bound to the same site in Settings → Domains.

## Links And Locale

Use Talizen's `<Link>` for multilingual internal links. Use `localizedPath()`
for raw URL strings. Never use router libraries.

```tsx
import { Link, useLocale } from "talizen"

<Link href="/blog/hello">Read</Link>

function LangSwitcher() {
  const { locales } = useLocale()
  return locales.map((locale) => (
    <Link key={locale} href="/" locale={locale}>{locale}</Link>
  ))
}
```

`CREGHT_LOCALE` represents explicit user choice. Detection order for unprefixed
paths: cookie, `Accept-Language`, then default locale.

Read locale with `getLocale()`/`context.locale` server-side and `useLocale()` in
components. Do not parse URLs for locale.

## UI Text

Use `/messages/{locale}.json` plus `useTranslations()` in components or
`getTranslations()` server-side for strings written in code. Keep the default
locale file complete; missing keys fall back to it.

## CMS Storage

Base fields are default locale. Translations for other locales live under
`_i18n[locale]`, only for localizable fields.

```json
{
  "title": "Hello",
  "slug": "hello",
  "_i18n": {
    "zh": { "title": "你好", "slug": "ni-hao" }
  }
}
```

Usually localizable: title, summary, body, slug, SEO text, alt text, captions,
button labels. Usually not localizable: ids, booleans, numbers, dates, enum
values used in logic, relations, and media URLs.

Keep enum values stable and translate labels with `enumLabelsI18n`.

## Slugs And Relations

Slugs are localized output, not stable identity. Anchor joins and relations on
stable item ids. A relation points to one item that resolves fields for the
current locale.

## Workflow

1. Add `i18n` config.
2. Mark only text-like CMS fields localizable.
3. Keep shared pages unless layout differs.
4. Write translations under `_i18n[locale]`.
5. Use `/messages` for static UI copy.
6. Verify links use `<Link>` or `localizedPath()`.
